# 性能模型
## Roofline型
~~这个模型的名字来源于像屋顶的折线吗,pvz那种~~![[roofline.png]]

- 算术强度 $I = \frac{W}{Q}$,其中 $W$ 为计算量(FLOPs),$Q$ 为数据量(Byte);
- 如图,随着算术强度 $I$ 增大,性能先是**线性上升**(此时memory bound),之后达到**峰值性能**趋于平稳(此时compute bound)。
- 拐点处的算术强度称为**机器平衡点**(ridge point), 记为 $I_{ridge} = \frac{P_{peak}}{BW}$;一般CUDACore的ridge point小于TensorCore。

## Little's Law
$$\overline{L} = \lambda \cdot \overline{W}$$
- 其中$\overline{L}$ 为**并发度**(在途字节数), $\lambda$ 为**吞吐量**(带宽), $\overline{W}$ 为**平均延迟**。
- 我们的目标是打满带宽,故需要 **高并发 × 低延迟**;但通常延迟是硬件限制,所以需要提高并发度(比如通过 **CUDA Stream** 并发)。
- 影响每SM在飞字节数的因素:驻留warp数,单指令字节数,MLP(memory level parallelism)
- 故高occupancy不是最终目标,高**并发度**才是;反之,**低occupancy但高占用率**的发射也可以达到高并发。甚至有时高occupancy会影响整体的性能

# 打满内存带宽

- [[02-性能优化初步#Little's Law|Little's Law(如上)]]
- **展开**:展开循环,把无依赖的指令尽量放一起,减少指令间延迟;增加带宽利用。(*话说我感觉这个就是很小的一个点,没必要单独一提?*)
- **Occupancy**:Occupancy是带宽利用的影响因素,通常会受到寄存器数量和共享内存大小限制;
- **向量化访存**:用128 bit访存指令,如`float4`,`int4`,可以减少指令数,提高带宽利用率;
- **coalescing**:同一warp访问连续内存地址,硬件会将请求合并为最少次数的事务;如果访问不连续,会拆分成更多事务,导致带宽浪费;
	- 32bytes=1 ==sector==
	- L1 to L2 :1 sector;L2 to Global :2 sector (default)
	- 1 ==cache line===128bytes=4 sectors.L1从**global**取数据是一次一行的cache line;为了高效访存,一个warp访问的地址必须覆盖尽可能少的cache line(顺序没有要求),否则会出现获取无用数据的浪费;同时要注意对齐,也能减少数据行的覆盖数量。
	- **A(rray)o(f)S(tructures) VS SoA**:当访问多个同类型结构体的某个字段时,AoS由于结构体内的字段分布不连续,会占据多条cache line,会导致读入无用字段;SoA所有该字段连续,访存更高效。
	- **bank conflict**:在share memory中,数据储存在32个bank上,每个bank宽度4 bytes(即bank地址 = (addr / 4) % 32);如果同一warp在**同一条共享内存指令**访问了**同一个bank的不同地址**,会有bank conflict,导致串行化。而同时访问同一个地址则会被广播,不算conflict。 ^62fee3

## MEMORY HIERARCHY
Memory Hierarchy是内存层次结构的意思,接下来要通过Reduce(求和)的例子,来介绍如何通过内存层次来优化

### v1:原子相加
```cpp
__global__ void reduce_v1(
const float* x, float* out, int n)
{
    int i = blockIdx.x * blockDim.x
            + threadIdx.x;
    if (i < n)
        atomicAdd(out, x[i]);
}
//197 ms，1.4 GB/s
```
- 非常简答的代码,原子相加会导致串行化,性能极低,还有严重竞争

### v2:block内求和,最后atomicadd
```cpp
__global__ void reduce_v2(
const float* x, float* out, int n)
{
    __shared__ float s[BLOCK];
    int tid = threadIdx.x;
    int i = blockIdx.x*blockDim.x + tid;
    s[tid] = (i < n) ? x[i] : 0.0f;
    __syncthreads();

    for (int stride = 1;
         stride < blockDim.x; stride *= 2) {
        if (tid % (2*stride) == 0)
            s[tid] += s[tid + stride];
        __syncthreads();
    }
    if (tid == 0) atomicAdd(out, s[0]);
}//1.67 ms，160 GB/s，118x
```
![[Pasted image 20260821154653.png]]
- 为了减少串行,首先在block内将数据recude,汇聚为lane0所属的值,最后原子相加。
- 使用smem来储存thread共同访问的数据
- warp divergence非常严重

### v3:减少warp divergence
```cpp
__global__ void reduce_v2(
const float* x, float* out, int n)
{
    __shared__ float s[BLOCK];
    int tid = threadIdx.x;
    int i = blockIdx.x*blockDim.x + tid;
    s[tid] = (i < n) ? x[i] : 0.0f;
    __syncthreads();

    for (int stride = 1;
         stride < blockDim.x; stride *= 2) {
        int idx = 2 * stride * tid;
        if (idx < blockDim.x)
            s[idx] += s[idx + stride];
            __syncthreads();
    }
    if (tid == 0) atomicAdd(out, s[0]);
}//0.87 ms，308 GB/s，1.9x
```
- 与v2相比,循环次数和计算内容完全一样,唯一不同的是分配工作给thread的方式。
- v3尽量让同一warp的thread一起计算,减少了warp divergence,避免"1thread计算,31thread围观",减少了资源浪费
- 去除模运算也减少了计算量
- [[02-性能优化初步#^62fee3|bank conflict]]:对一个thread来说,覆盖的范围是2,4,8......逐渐增加,由于这段代码尽量让一个warp的thread同时工作,那么一个warp内只要有32,16,8,4......个thread工作就能出现很大的bank conflict,更何况在stride比较小时,一个warp内总是32个thread工作,那么就会有多个thread访问一个bank.**一个warp里面的thread只访问了少数几个bank,必然冲突**

### v4:处理bank conflict
```cpp
__global__ void reduce_v4(const float* __restrict__ x, float* out, int n) {
    __shared__ float s[BLOCK];
    int tid = threadIdx.x;
    int i = blockIdx.x * blockDim.x + tid;
    s[tid] = (i < n) ? x[i] : 0.0f;
    __syncthreads();
    for (int stride = blockDim.x / 2; stride > 0; stride >>= 1) {
        if (tid < stride) s[tid] += s[tid + stride];
        __syncthreads();
    }
    if (tid == 0) atomicAdd(out, s[0]);
}//0.78 ms，344 GB/s
```
![[Pasted image 20260822150106.png]]

- 正如上文分析,v3出现了一个warp只访问几个bank的问题,如果把stride从blockdim.x/2开始不断减半,让**一个warp的thread访问的地址刚好是连续的**,那么一个warp访问的bank是32个连续的bank,完全没有冲突。
- block数随n增加而增加,大量atomicadd


## v5:gridDim.x = SM数 * 16
```cpp
//之前: gridDim.x = ceil(n / blockDim.x)
//现在: gridDim.x = SM数 * 16
__global__ void reduce_v5(const float* __restrict__ x, float* out, int n) {
    __shared__ float s[BLOCK];
    int tid = threadIdx.x;
    float sum = 0.0f;
    for (int i = blockIdx.x * blockDim.x + tid; i < n; i += gridDim.x * blockDim.x)
        sum += x[i];
    s[tid] = sum;
    __syncthreads();
    for (int stride = blockDim.x / 2; stride > 0; stride >>= 1) {
        if (tid < stride) s[tid] += s[tid + stride];
        __syncthreads();
    }
    if (tid == 0) atomicAdd(out, s[0]);
}//0.25 ms，1074 GB/s
```

- 一个block处理多块数据,block数量减少,atomicadd减少,调度and启动开销减少
- 在寄存器进行累加,共享内存只被用于最终的归约,减少shared memory访问。
- 每个sm上有16个block足够打满整个sm,减少同步开销。

### v6:Warp Shuffle Primitives

```cpp
__device__ float warp_reduce_sum(float v) {
    for (int off = 16; off > 0; off >>= 1)
        v += __shfl_down_sync(0xffffffff, v, off);
    return v;   // 结果只在 lane 0 有效
}

__global__ void reduce_v6(const float* __restrict__ x, float* out, int n) {
    __shared__ float s[BLOCK / WARP];
    int tid = threadIdx.x;
    int warp_id = tid / WARP;
    int lane_id = tid % WARP;
    float sum = 0.0f;
    for (int i = blockIdx.x * blockDim.x + tid; i < n; i += gridDim.x * blockDim.x)
        sum += x[i];
    sum = warp_reduce(sum);//自定义函数
    if (lane_id == 0) s[warp_id] = sum;
    __syncthreads();
    if (warp_id == 0) {
        sum = (lane_id < blockDim.x / WARP) ? s[lane_id] : 0.0f;//block中的线程数必须小于1024,故blockDim.x / WARP<=32必定成立(nb!)
        sum = warp_reduce(sum);
        if (lane_id == 0) atomicAdd(out, sum);
    }
}//0.247 ms，1087 GB/s
```
当活跃的线程少于等于32个时,线程在一个warp内天然同步,可以在一个warp内使用warp shuffle
#### Warp shuffle
| 指令                 | lane `i` 获取  | 典型用途                 |
| ------------------ | ------------ | -------------------- |
| `__shfl_sync`      | 指定 lane      | 广播、置换                |
| `__shfl_up_sync`   | `i - delta`  | prefix sum、stencil   |
| `__shfl_down_sync` | `i + delta`  | 归约到 lane 0           |
| `__shfl_xor_sync`  | `i xor mask` | butterfly all-reduce |
- `mask` 必须准确描述参与 lane；活跃分支与 mask 不一致可能产生未定义行为，可用 `__activemask()` 构造实际 mask。
- `width` 可把 warp 分成多个独立子段，例如 `width=8` 表示四个 8-lane 小组。

### v7:向量化
```cpp
__global__ void reduce_v7(const float4* __restrict__ x4, float* out, int n4) {
    float sum = 0.0f;
    for (int i = blockIdx.x * blockDim.x + threadIdx.x; i < n4;
         i += gridDim.x * blockDim.x) {
        float4 v = x4[i];
        sum += v.x + v.y + v.z + v.w;
    }
    sum = warp_reduce_sum(sum);//自定义函数
	//以下基本和v6相同
    __shared__ float warp_sum[32];
    int lane = threadIdx.x & 31;
    int wid  = threadIdx.x >> 5;
    if (lane == 0) warp_sum[wid] = sum;
    __syncthreads();

    if (wid == 0) {
        sum = (lane < blockDim.x / 32) ? warp_sum[lane] : 0.0f;
        sum = warp_reduce_sum(sum);
        if (lane == 0) atomicAdd(out, sum);
    }
}//0.17 ms，1572 GB/s
```
- 向量化访存,减少指令数,提高带宽利用率,从1087 GB/s提升到1572 GB/s.

# FP32 GEMM
- GEMM指的是通用矩阵乘(General Matrix Multiply.),假设A：M\*K,B：K\*N,C:M\*N.
- 并行:拆分数据与计算
- 计算公式:$$C[i,j]=\sum_{k=1}^K A[i,k] \cdot B[k,j]$$
- $$\text{理论AI}=\frac{M  N  K}{2(M  K + K  N + M  N)}\text{Flops/Byte}$$

## v1:一个线程负责一个元素

- ~~非常简单好写啊~~
- 对于一个线程,访问了2K个输入一个输出,做了K次乘加, AI=K/(4K+2)≈0.25Flops/Byte.数据复用太少了,计算访存比极低。

## v2:在smem中复用数据
![[Pasted image 20260822181546.png]]

- 如图,一个CTA首先将A，B中子矩阵载入smem,然后进行乘法计算,使得数据可以复用,沿k方向重复乘法和加法,得到C中的子矩阵
- 
$$AI = \frac{2 B_M B_N K}{4K(B_M+B_N) + 4B_M B_N} \approx \frac{2 B_M B_N K}{4K(B_M+B_N)} = \frac{B_M B_N}{2(B_M+B_N)}$$
- 可见AI会随着tile的增大而增大,但是此时由于thread的有数量限制,数据复用受阻
- 对齐最连续的维度
	- cuda规定,thread的序号为$$tid = threadIdx.x+blockDim.x*(threadIdx.z * blockDim.y+threadIdx.y) $$
	- 对于A、B、C来说,最连续的维度是最后一个维度(A的k维度,B的n维度,C的n维度。),因此在从**gmem**(注意是gmem,smem的特点很不一样)中读取时,尽量让一个warp在**最后一个维度**连续。
- smem压力很大,成为瓶颈

## v3:thread处理更多数据
- 在一个thread中处理更小的tile,从而减少了smem的压力
- 解放了thread的数量,让一个block能通过**更大的tile**来让复用性更好。
